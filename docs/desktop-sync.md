## 每次保存的顺序

1. 检查本地状态与远程 `main`，有更新先核对再合并，保留已有记录。
2. 在桌面对应章节写入记录和配图，更新中文导航与仓库章节入口。跨文件链接采用相对路径，使 GitHub 和本地 Markdown 阅读器都能使用。
3. 用 `git diff`、待提交文件列表检查实际范围，确认图片和链接存在，不用整目录盲目添加实验、缓存或原卷包。
4. 提交并推送到远程，核对远程提交及文件内容。常规 Git 推送不可用时，可使用已授权的 GitHub 连接器提交，再抓取该提交使本地分支一致。
5. 向用户报告实际上传结果；失败时明确说明本地已保存、远程未完成，不把本地提交说成已经上传。

常规 Git 客户端可在该目录使用 `git fetch origin`、`git status` 检查更新；正常提交后用 `git push origin main` 上传。连接器授权与 Git 客户端登录分别管理，连接器可用不表示 Git 命令行已经登录。

不使用强制推送覆盖远程，不删除或移动桌面资料。需要处理有冲突的同名笔记时，先保留两个版本再核对。
